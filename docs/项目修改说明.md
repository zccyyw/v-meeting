## 2026-08-06 修改说明（修复 ws_not_connected / client_closed 错误）

- **类型**：修复
- **说明**：修复 React StrictMode 双挂载下 WebSocket 连接错误。`queueMicrotask` 延迟创建 WS 后，微任务检查 `this.closed` 为 `true` 时的处理方式经过三次迭代最终确定：1）`resolve()` → `connect()` 成功但 `this.ws` 为 `null`，`join()` 继续到 `send()` 抛 `ws_not_connected`；2）`reject("client_closed")` → 错误被 `.catch()` 捕获但 `console.error` 仍然打印到控制台；3）最终方案：**不 resolve 也不 reject**，Promise 保持 pending，`join()` 的 `await connect()` 挂起但不会到达 `send()`，cleanup 中 `room.leave()` 的 `signal.send()` 有 `try/catch` 保护，SignalClient 实例被 GC 回收，第二次 mount 正常工作。

## 2026-07-26 · 修复 mediasoup 在国内/老内核服务器 Docker 构建失败

- **修改类型**：构建修复
- **描述**：
  - 根因：mediasoup 3.22.0 未发布 kernel<6 的 Linux x64 预编译 worker，CentOS 7（内核 3.10）无法下载预编译包；回退本地编译时，meson 需从 WrapDB（`wrapdb.mesonbuild.com`）和 libuv/openssl 官方源下载依赖，这些域名在国内网络超时，导致构建失败
  - 解决：改用本地编译，并通过脚本重写 mediasoup 的 meson wrap 文件，把所有依赖下载 URL 重定向到 gh-proxy + GitHub wrapdb releases（国内可达）
  - Dockerfile 改为 `npm ci --ignore-scripts` 装依赖后，先用 `patch-mediasoup-wrap.cjs` 改写 wrap URL，再手动触发 mediasoup postinstall 编译 worker
  - pip 默认走清华源下载 meson/ninja/invoke
  - 支持构建参数覆盖：`--build-arg GHPROXY=` 换代理、`--build-arg PIP_INDEX_URL=` 换 pip 源
- **涉及文件**：
  - `serve/realtime/Dockerfile` -- 重构 mediasoup 构建流程
  - `serve/realtime/patch-mediasoup-wrap.cjs` -- 新增，通用化重写所有 meson wrap 文件的下载 URL
