## 二、发现缺陷清单

### 缺陷 #1 — Zod 校验错误返回 500 而非 400（严重）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | BUG-001 |
| **严重级别** | 高 |
| **影响范围** | 所有使用 Zod `.parse()` 的 API 端点 |
| **涉及用例** | TC-AUTH-010a, TC-AUTH-010b, TC-GRP-013, TC-GRP-015, TC-APP-012 |
| **现象** | 当请求体不符合 Zod schema 时，服务端返回 HTTP 500（Internal Server Error），而非 HTTP 400（Bad Request） |
| **根因** | `serve/api/src/index.ts` 中未注册 Fastify 全局错误处理器（`setErrorHandler`），Zod `.parse()` 抛出的 `ZodError` 未被捕获，Fastify 默认将其作为 500 错误处理 |
| **复现步骤** | `POST /auth/login` body=`{"username":"","password":"123456"}` → 返回 500 |
| **预期修复** | 在 Fastify 实例上注册 `setErrorHandler`，捕获 `ZodError` 返回 400 + 详细校验错误信息 |

### 缺陷 #2 — 密码特殊字符校验正则错误（严重）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | BUG-002 |
| **严重级别** | 高 |
| **影响范围** | 密码策略模块 — 特殊字符校验 |
| **涉及用例** | TC-PWD-007 |
| **现象** | 密码 `Abcdefg123`（无特殊字符）修改成功，但策略要求 `requireSpecial=true` |
| **根因** | `serve/api/src/password-policy.ts` 第 82-83 行，`escapeRegex` 函数未正确处理字符类内的 `-` 符号。特殊字符集 `!@#$%^&*()_+-=[]{}|;:,.<>?/` 中的 `+-=` 在正则字符类 `[]` 中被解释为范围（`+` 到 `=`），该范围包含了数字 `0-9`、部分标点符号，导致包含数字的密码被误判为含有特殊字符 |
| **复现步骤** | 1. 登录 test4 → 2. `POST /auth/change-password` body=`{"currentPassword":"Abcd@123","newPassword":"Abcdefg123"}` → 3. 返回 200（应返回 400） |
| **预期修复** | 修改 `escapeRegex` 函数，在字符类中对 `-` 进行转义，或将其放在字符类的开头/末尾位置 |

### 缺陷 #3 — 审批创建的新用户登录崩溃（严重）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | BUG-003 |
| **严重级别** | 高 |
| **影响范围** | 用户操作审批 — create 类型审批通过后新用户登录 |
| **涉及用例** | TC-APPR-002b, TC-E2E-003c |
| **现象** | 通过审批创建的新用户登录时返回 500，错误信息：`pwdUpdateDate.endsWith is not a function` |
| **根因** | `serve/api/src/routes/sys-user-approval.ts` 第 193 行，`pwd_update_date` 设置为 `${nowSql(db)}`（即 SQL `NOW()` 函数），MySQL 返回 `Date` 对象。而 `serve/api/src/password-policy.ts` 第 117 行 `isPasswordExpired` 函数调用 `pwdUpdateDate.endsWith()`，`Date` 对象没有 `endsWith` 方法 |
| **复现步骤** | 1. sysadmin 提交 create 审批 → 2. authadmin 审批通过 → 3. 新用户登录 → 500 |
| **预期修复** | 在 `isPasswordExpired` 函数中增加类型检查，若 `pwdUpdateDate` 为 `Date` 对象则先转为 ISO 字符串再调用 `endsWith` |

### 缺陷 #4 — 重复邀请未被唯一约束忽略（中等）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | BUG-004 |
| **严重级别** | 中 |
| **影响范围** | 会议邀请 — 重复邀请处理 |
| **涉及用例** | TC-INV-005 |
| **现象** | 对同一会议中已邀请的用户再次邀请，`invited` 计数仍为 1（应被忽略为 0），未触发 `isUniqueViolation` |
| **根因** | `meeting_invitations` 表可能缺少 `(meeting_id, user_id)` 的唯一约束，导致 `INSERT` 不会触发唯一键冲突，`isUniqueViolation` 永远不匹配 |
| **预期修复** | 在 `meeting_invitations` 表上添加 `UNIQUE KEY (meeting_id, user_id)` 约束 |

### 缺陷 #5 — 禁用用户仍可登录（中等）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | BUG-005 |
| **严重级别** | 中 |
| **影响范围** | 登录认证 — 禁用用户检查 |
| **涉及用例** | TC-AUTH-008 |
| **现象** | 通过 `PATCH /sys-user/:id` 将用户 status 改为 1（禁用）后，用户仍能登录 |
| **可能原因** | 需进一步确认 `PATCH /sys-user` 是否正确更新了 status 字段，或者测试脚本的 PATCH 请求未成功。auth.ts 第 102 行确实有 `if (row.status !== "0" || row.del_flag === "2")` 检查 |
| **预期修复** | 需进一步排查 `sys-user` 的 PATCH 接口是否正确处理 status 字段更新 |

### 缺陷 #6 — 配置更新接口缺失（低）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | BUG-006 |
| **严重级别** | 低 |
| **影响范围** | 系统配置 — 在线人数限制修改 |
| **涉及用例** | TC-LMT-004b |
| **现象** | `PUT /sys-config` 路由不存在（404） |
| **根因** | `serve/api/src/routes/sys-config.ts` 可能只提供了 GET 接口，缺少 PUT/PATCH 更新配置的路由 |
| **预期修复** | 添加 `PUT /sys-config` 或 `PATCH /sys-config/:key` 路由用于更新配置项 |

## 六、测试结论

本次测试在 API 层面执行了 77 条用例，通过率 83.1%，发现 6 个代码缺陷。其中 3 个为 P0 级别（影响核心业务流程），需优先修复。

**主要发现**：
1. **输入校验缺陷**：全局 Zod 校验错误处理缺失，所有输入校验失败都返回 500 而非 400，影响用户体验和错误处理
2. **安全缺陷**：密码特殊字符校验失效，导致不含特殊字符的密码可设置成功，降低了密码强度
3. **业务阻断缺陷**：通过审批创建的新用户无法登录，阻断了三员管理端到端流程

**建议**：
- 优先修复 3 个 P0 缺陷
- 补充前端浏览器测试和 WebSocket 信令测试
- 修复后执行回归测试
