# 信创国产化服务器适配方案

> 日期：2026-09-08
> 依据：《XC客户端和服务器系统说明 v1.0》（`docs/XC客户端和服务器系统说明-v1.0.md`，源文件 xlsx）

## 1. 目标与范围

将现有打包产物（RPM / DEB / Native tar.gz / Docker 镜像）扩展支持信创国产服务器操作系统：

| 类型 | 操作系统 | 架构 | 安装方式 |
|---|---|---|---|
| 服务器 | 银河麒麟、中科方德 | loongarch64 / aarch64 / x86_64 | 离线 |
| 客户端 | 银河麒麟 / 统信 V10 SP1、统信专业版 1050 | loongarch64 / aarch64 / x86_64 | 离线（浏览器访问） |

- 服务器无 JAVA 运行时（本系统为 Node.js 技术栈，无依赖）；支持 Nginx。
- **loongarch64（龙芯）为必选架构**。
- 客户端为桌面环境浏览器访问（Web/PWA），无需在客户端安装 Nginx/JAVA。

## 2. 现状与兼容性分析（实测数据）

现有产物基于 `node:22-bookworm`（Debian 12，**glibc 2.36**）构建：

| # | 检查项 | 实测结果 | 影响 |
|---|---|---|---|
| 1 | 构建基线 glibc | Debian 12 = **2.36** | 麒麟 V10 SP1（**2.17**）、SP2/SP3（**2.28**）、UOS20（2.28）均低于 2.36，二进制报 `GLIBC_2.36 not found` |
| 2 | Node 22 官方二进制 glibc 要求 | ≥ **2.28** | SP1 无法运行官方 Node 22 |
| 3 | Node 22 unofficial 构建可用性 | x64 **glibc-217 ✅（200）**；arm64 glibc-217 **❌（404）**；**arm64-musl ✅（200）**；**loong64 ✅（200）** | x86_64 SP1 有现成运行时；**aarch64 SP1 无**（需 musl 兜底或本地编译/系统 Node） |
| 4 | mediasoup 3.22.0 官方预编译 worker | **仅 kernel6 变体**（kernel4/5 实测 404），且仅 x64/arm64 | 麒麟/UOS 内核 4.19/5.4 **必须本地编译**；**loongarch64 无任何预编译** |
| 5 | systemd 单元语法 | 使用 `StandardOutput=append:`，要求 **systemd ≥ 240** | 麒麟 SP1(219)/SP2(239) **全系不支持，服务启动失败**——现存代码缺陷 |
| 6 | 包格式 | fpm RPM（`--no-auto-depends`）/ DEB / tar.gz，自包含 | 格式本身通用，问题全在二进制基线 |

## 3. 架构 × 组件可行性矩阵

| 架构 | Node 22 运行时 | mediasoup worker | better-sqlite3 |
|---|---|---|---|
| x86_64 | 官方（glibc≥2.28）✅；glibc-217 ✅ | kernel6 预编译 ✅ / 本地编译 | 官方 prebuild ✅ |

| loongarch64 | unofficial `linux-loong64` ✅ | **必须本地编译** | **必须本地编译** |

## 4. 方案

### 4.1 A′ 档（主推）：目标机本地离线构建

三架构 × 多版本 × 全离线，本地构建是唯一通吃路径（目标机 glibc/gcc 与产物天然匹配，零兼容风险）。

**离线构建包（Offline Build Bundle）** 组成：

| 组成 | 内容 |
|---|---|
| 源码 | 仓库源码（不含 node_modules） |
| Node 运行时 | 按架构自动选择：x86_64 → 官方 / glibc-217；aarch64 → 官方(2.28) 或 musl；loongarch64 → `linux-loong64` |
| npm 离线依赖 | `npm cache` / node_modules tarball（`npm ci --offline`） |
| Python 离线包 | **meson / ninja / invoke 的 wheel**（mediasoup worker 本地编译必需，内网无 PyPI） |
| `build-local.sh` | 探测 OS/版本/架构/glibc/systemd → 选运行时 → 离线装依赖 → 编译 worker 与 better-sqlite3 → 构建前端 → 产出 RPM/DEB/tar → 按 systemd 版本安装对应 unit |

产出：`meeting-<ver>.<arch>.rpm`（麒麟/方德）、`.deb`（方德 DEB 系），或直接运行的 `/opt/meeting`。

### 4.2 B′ 档（补充）：x86_64 / aarch64 预编译包

Linux 构建机按 **glibc 2.28 基线**产出 RPM/DEB，覆盖麒麟 SP2/SP3、中科方德、openEuler；SP1（glibc 2.17）：x86_64 走 glibc-217 Node，**aarch64 走 A′ 档**。

### 4.3 C′ 档（可选）：容器化

x86_64 / aarch64 可沿用现有镜像（服务器支持 Nginx，环境相对开放）；**loongarch64 不建议**（无官方 node 基镜像）。

## 5. 通用必改项与功能影响评估

| # | 改动 | 性质 | 对现有功能的影响 |
|---|---|---|---|
| 1 | systemd 单元去除 `StandardOutput=append:`（219/239 不支持，麒麟上服务无法启动） | **缺陷修复**，非降级 | 无功能损失；日志查看方式变化（`journalctl -u meeting-api` 或 `ExecStart=/bin/sh -c 'node ... >> /opt/meeting/logs/api.log 2>&1'`）。倾向保留文件日志（现有排障文档依赖） |
| 2 | 单元语法收敛到 systemd 219 兼容子集，按版本提供 unit | 适配 | 无 |
| 3 | glibc 基线按目标最低版本构建 | 构建参数 | 无功能差异（Node 同版本、不同工具链构建） |
| 4 | mediasoup worker 本地编译（低内核无预编译） | 构建方式 | 无功能差异 |
| 5 | worker 链接加 `-static-libstdc++ -static-libgcc` | 编译参数 | 无；规避目标机 libstdc++ 过旧 |
| 6 | Node 运行时按架构选型（glibc-217 / musl / loong64） | 运行时来源 | 同版本功能一致；musl 构建性能略低、需验证原生模块编译 |
| 7 | 增加 **H264** 协商编码（当前仅 opus+VP8） | **增益** | 无负面影响。服务器为 SFU 纯转发不参与编解码，无授权问题；客户端 Chromium 系自带 OpenH264 |
| 8 | SELinux（麒麟默认 enforcing）：8088 端口策略 | 部署配置 | 无；不加则网关端口被拒（部署说明中给出 `semanage port` 或策略文件） |
| 9 | 防火墙：firewalld 放行 8088 / 8080 / UDP 40000-40100 | 部署配置 | 无 |
| 10 | Nginx 反代（复用 `deploy/native/conf/nginx-meeting.conf`） | 部署配置 | 无 |

## 6. 客户端（浏览器）适配

客户端为桌面环境浏览器访问，适配点与影响：

| 风险点 | 现状 | 改动建议 | 影响 |
|---|---|---|---|
| 构建目标过高 | Vite 8 默认 `baseline-widely-available`（约 Chrome 107+），奇安信 Chrome 102、UOS 浏览器可能不满足 | 显式设置 `build.target: 'es2020'`（或 chrome100） | **经代码扫描：业务代码零使用 es2022+ 运行时 API（structuredClone / Object.hasOwn / .at() / toSorted 等均未出现）、零现代 CSS 特性（:has/@layer/oklch/@container）** → 语法转译即可覆盖，无 API 缺失风险 |
| 视频编码协商 | router 仅 opus + VP8 | 增加 H264 | 无损失，多一种协商选择 |
| 自动播放策略 | 已针对奇安信 Chrome 102 做 `muted` 属性兜底（`VideoTile` 内有显式 `el.muted` + `play()` 兜底） | 保持并实机复测 | 无 |
| 屏幕共享 | `getDisplayMedia`（room.ts），已有自共享回环消除 | 老 Chromium 实机验证；不支持时共享按钮提示降级 | 屏幕共享为可选功能，不影响音视频核心能力 |
| PWA 安装提示 | `useInstallPrompt` | 部分国产浏览器不支持 `beforeinstallprompt` → 提示不出现 | 边缘功能，可接受（浏览器直接访问不受影响） |
| 离线资源 | `index.html` 无 CDN 外链 ✅；PWA precache 59 项 | 保持 | 内网离线可用 |
| 第三方库基线 | React 19 + AntD 6 + mediasoup-client 3.21 | **需在目标浏览器（奇安信/UOS 浏览器/火狐 ESR）实机验证**，AntD 6 的浏览器基线是最大未知项 | 待实测确认 |

## 7. 「降级」对现有功能的影响总结

**结论：影响接近零。** 具体拆解：

| 维度 | 评估 |
|---|---|
| 前端语法 | esbuild 编译期转译（es2020 目标），**零影响**；业务代码已扫描确认无高版本 API 依赖 |
| 前端运行时 API | 仅 `getDisplayMedia`（屏幕共享），Chromium 系信创浏览器均支持；不支持时仅共享功能不可用，音视频核心不受影响 |
| 前端 CSS | 零使用现代特性，零影响 |
| Node 后端功能 | 同版本 Node 的不同构建（glibc-217/musl/loong64），**功能与 API 完全一致**；Node 22 静态自带 OpenSSL 3，不依赖系统 OpenSSL |
| mediasoup worker | 本地编译与预编译产物功能一致；静态链接 libstdc++ 后与目标机环境解耦 |
| systemd 日志 | 由 `append:` 文件改为 journal 或 shell 重定向，仅**排障方式**变化，无功能损失 |
| 视频编码 | 增加 H264 为纯增益 |
| 性能 | loongarch64 单核较弱，但 SFU 为纯转发（不在服务端编解码），压力可控；建议以「20 路在线」目标实测 |

**唯一可能的功能可用性差异**在浏览器侧（PWA 安装提示、屏幕共享等边缘能力），核心会议能力（入会、音视频、共享、聊天、管控、录制）在 Chromium 内核浏览器上均可保留，需以真机实测为准。

## 8. 工作量与实施路线

| 阶段 | 内容 | 工作量 |
|---|---|---|
| 0 | **loongarch POC**：借龙芯机器验证 mediasoup worker + better-sqlite3 本地编译（决定整体投入） | 1~2 人日 |
| 1 | systemd 单元兼容修复 + Vite target + H264 编码扩展 | 2 人日 |
| 2 | A′ 离线构建包（wheels、多架构运行时、`build-local.sh`） | 5~8 人日 |
| 3 | B′ 预编译包（glibc 2.28 基线，x86_64/aarch64） | 2~3 人日 |
| 4 | 真机验证（麒麟 SP1/SP3、方德、UOS × 三架构 × 桌面浏览器） | 3~5 人日 |

验证环境建议：华为云/阿里云的麒麟、UOS 按量镜像 + 客户提供的龙芯机器。

## 9. 待确认项

1. 服务器麒麟/方德的具体版本（SP1 glibc 2.17 还是 SP2+ 2.28）——决定 aarch64 是否可用预编译包。
2. loongarch64 的优先级确认（建议先 POC）。
3. 客户端浏览器型号与内核版本（奇安信 / UOS 浏览器 / 火狐 ESR）。
4. 服务器是否允许安装 Docker/Podman（允许则 x86_64/aarch64 可直接走容器交付）。
